# 联副产物生产批台账与独立批次成本仓（Python 3.11）

同一批原料产生主产品、副产品与损耗；更正产量时，成本仓按真实消耗比例重算全链，
而不是只改主产品单价让总成本失衡。本项目用**合成数据自定义全部规则**，
不模拟任何现实财务准则，不做会计凭证、税务或采购预测。

仅使用 Python 3.11 标准库（`fractions`、`sqlite3`、`unittest`、`dataclasses`），
无第三方依赖。

## 运行

```bash
python3 -m unittest discover -s tests -v   # 39 个测试
python3 -m ledger_cost.demo /tmp/plant.db  # 端到端演示（落盘后可重开）
```

## 模块边界

| 模块 | 职责 | 关键约束 |
| --- | --- | --- |
| `ledger_cost/production.py` | 生产登记、可用量、多级 DAG 谱系、修订/撤销、物料去向查询 | 无任何成本依赖，可独立运行 |
| `ledger_cost/cost.py` + `engine.py` | 版本化成本输入、精确有理数成本传递、发布舍入、全量/增量重算、来源解释 | 只消费只读生产快照 `Snapshot`，无写产量路径，不能从成本表反推产量 |
| `ledger_cost/storage.py` | SQLite 持久化 | 修订与成本切面**只追加**，旧行/旧产品永不删除，关闭重开可查 |
| `ledger_cost/checks.py` | 独立守恒核验 | 不复用引擎计算路径，直接从台账+产品重算 |

## 生产台账规则（合成定义）

- 按 `batch_id` 登记：投入批号、投入整数克、各产出 `lot_id` 与整数克、不可回收损耗克。
- 守恒硬约束：`Σ 产出克 + 损耗克 == 实际投入克`；零克产出禁止登记（违反即拒绝，不落库）。
- 一个批号**至多作为一次生产的投入来源**；允许部分投入，累计消耗不得超过该批可用量。
- 多级有向无环谱系：禁止消费自己（未来）的产出，禁止成环。
  规模上限：最多 20 生产批、每批最多 5 产出、谱系深度上限 6。
- 已发布批次不原地改写：
  - **更正** → 新建修订（旧修订置 `superseded` 永久保留）；
    若任一出产批号的拟保留克数小于下游已实际消耗克数，**整次拒绝**
    （`RejectedByConsumption.blocking` 给出 `(lot_id, 拟保留, 已消耗)`）。
  - **撤销** → 置 `cancelled`；任一出产批号已被下游实际消耗即拒绝；
    撤销后投入批号可用量恢复。
- 查询：`available(lot_id)`、`trace_lot(lot_id)`（来源/产量/消耗/留存/下游）、
  `list_revisions(batch_id)`（含全部历史修订）。

## 成本仓规则（合成定义）

### 版本化输入（均为整数分，显式版本号）

- 期初原料总成本（`root-v1`、`root-cent` …）
- 各生产批额外加工费（`fee-v1` …）
- 各产出批单位参考价值，允许为零（`ref-v1`、`ref-v2` …）

### 精确传递

- 对固定生产切面，从根原料沿**真实消耗比例**
  （投入克数 / 批号实际产量）以 `Fraction` 精确有理数传递，全程无浮点。
- 根批号部分留存时，留存成本 = 精确单位成本 × 留存克数，同样保留。
- 每批：`待分配池 = 投入精确成本 + 加工费`，在其非零产出间按
  `产量 × 参考单位价值` 比例分摊；**损耗不分摊可出售成本**。
- 权重分母为零（如参考价值全为零）→ 该批及其全部依赖批标记**不可计价**，
  精确值/发布值一律为 `None`，**不填零**。

### 发布金额（整数分）

1. 整批待分配池先统一**四舍五入**（0.5 进位）到整数分；
2. 各产出按精确份额**下取整**，剩余分按**最大余数**补发；
   余数并列按 `lot_id` 字典序，结果完全确定；
3. 每批发布明细之和恒等于本批整数总额（测试逐批断言）。
4. 成本产品同时保留**精确值与发布值**；下游传递只用精确值，
   不逐层重复舍入。

### 重算与解释

- `mode="full"`：全量拓扑重算。
- `mode="incremental"`：依赖索引增量更新——比较两版成本输入与生产修订得到种子批，
  沿产出-消耗边取后代闭包，只重算闭包内批次，其余复用旧产品；
  demo 与测试对每个切面做全量/增量逐字段对拍，两口径必须完全一致。
- `explain_unit_change(new_cut, lot_id, old_cut)`：沿谱系定位**首个发生变化的祖先**，
  说明未直接改动批号的单位/总成本变化来源。

### 持久化

SQLite 文件中，生产修订（active/superseded/cancelled）与成本切面产品均追加保留；
关闭进程后用 `scenario.open_systems(path)` 重开，历史修订、历史切面与产品仍可查，
并可继续发布新切面。

## 合成场景覆盖（11 批 / 5 根批号 / 最大深度 4）

| 案例 | 位置 |
| --- | --- |
| 一投入两产出 + 部分投入（留存）+ 损耗 | B1（R1 投 600/1000g，损耗 20g） |
| 三级（实际四级）再加工谱系 | B1→B2→B3→B11，深度 1/2/3/4 |
| 中间批号部分投入与留存 | B4 仅投 L2B 60/90g |
| 参考价值为零 → 分母为零 → 不可计价且不填零 | B5（L5A 价值 0）及其依赖 B6 |
| 一分钱分摊（池 0.6 分 → 发布 1 分，三路等权） | B7 + `root-cent` 版本 |
| 后代已消耗阻止上游减量（整次拒绝、无新修订） | B8 消耗 L1B 后尝试更正 B1 |
| 无下游占用时更正成功并触发后代重算 | B9 修订 2 |
| 撤销释放投入可用量 | B10 撤销，R5 可用 30→50g |
| 价格更正（L2A 12→18）全量/增量对拍 + 单位变化解释 | cut-v1 → cut-v2 / cut-v2i |
| 关闭重开持久化 | demo 第 9 节、`tests/test_persistence.py` |

## 独立守恒核验（`checks.py`，不调用引擎内部算法）

- **质量**：每批 `投入 == 产出合计 + 损耗`；全局
  `根产量 == 全部批号留存合计 + 全部批次损耗`；任一批号消耗不超产量。
- **精确成本**：根 `期初成本 == 留存成本 + 根直接流出`；
  每个可计价批 `投入精确成本 + 加工费 == 产出精确成本之和`；
  不可计价区域无任何成本数字（含不填零检查）。
- **发布金额**：每批发布合计 == 精确池四舍五入值，且每个发布份额落在
  精确份额的下取整或下取整+1 范围内。
