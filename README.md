# 不停库盘点：冻结基准与差异调整工作台

盘点期间仓库仍在收发货。若把盘点数量直接覆盖到当前库存，盘点冻结之后发生的
真实出库会被“盘点数”吞掉。本项目用 Python 3.11 + 真实 SQLite 事务实现一套
**独立库存账本**与**盘点工作台**，核心口径是：

> 提交时不是“把当前量设为盘点量”，而是把
> **差异 = 盘点量（冻结时刻 k 的实数） − 账本 as_of(k)**
> 作为一笔新的真实库存调整原子发布。

## 手算例（`demo.py` 场景 1）

| 时刻 | 事件 | SKU-A@L01 |
| --- | --- | --- |
| seq=1 | 入库 10 | 10 |
| k=1 | 开始盘点，冻结基准 = 10 | 10 |
| — | 录入盘点实数 9（k 时刻口径） | 10 |
| seq=2 | 冻结后正常出库 3 | 7 |
| seq=3 | 提交差异 9 − 10 = **−1** | **6** |

- 错误对照：直接覆盖成 9 会吞掉冻结后的 3 件真实出库；
- 正确结果：当前 7 + 差异(−1) = **6**。

## 模块

| 文件 | 职责 |
| --- | --- |
| `ledger.py` | 独立库存账本：入库/出库/同 SKU 跨库位移动/差异调整，幂等申请、`commit_seq`、前缀快照、逐操作查询。可脱离工作台单独使用 |
| `workbench.py` | 盘点工作台：开单冻结、位置占用、录入与版本更正、差异计算、非负检查、原子提交、作废、逐项解释。**只调用账本公开接口，不碰库存表** |
| `audit.py` | 独立重放核账：只读底层事件表重放全量库存，核对当前量、全部快照、冻结基准、差异口径、占用一致性；可 `python3 audit.py <db>` 单独运行 |
| `synthetic.py` | 合成业务事件：固定随机种子的确定性收发/移动/盘点流，维护纯 Python 镜像库存做第二事实来源，强制覆盖各异常分支 |
| `demo.py` | 10 个端到端场景的主入口 |

## 关键设计

### 账本（`ledger.py`）

- **真实事务**：连接 `isolation_level=None`，所有写操作显式
  `BEGIN IMMEDIATE ... COMMIT/ROLLBACK`，WAL 模式 + `busy_timeout`。
- **全局递增 `commit_seq`**：以 `l_requests.rowid` 为序号，只有成功操作才占用；
  失败操作回滚后不留下序号、行或半次移动。
- **幂等申请**：`request_no` 为主键，正文用
  `json.dumps(..., sort_keys=True, separators=(",",":"))` 规范化。
  同号同文复读原回执；同号异文抛 `IdempotencyConflict`。
- **非负整数库存**：列级 `CHECK (qty >= 0)` + 事务内逐位置前置净增量校验，
  非法出库/穿零调整在写入前被拒；移动两侧同一 `commit_seq` 原子提交。
- **固定前缀快照**：`retain_snapshot(prefix, label)` 物化某前缀的全量数量，
  同一前缀可被多张盘点单共享（label 唯一）；`as_of(k)` 随时事件重放。
- **公开接口**：`inbound / outbound / transfer / adjust /
  retain_snapshot_in_tx / publish_adjustment_in_tx / as_of /
  get_snapshot / list_operations / get_operation / events_touching`。

### 工作台（`workbench.py`）

- **冻结**：开单在一个 IMMEDIATE 事务内读取账本头序号 `k`、物化快照、
  写入盘点行与位置占用，全部原子可见。
- **位置占用**：`active_count_locations` 以 `(sku, location)` 为主键，
  每个位置只能属于一张未关闭盘点单；重叠开单整次拒绝，无半成品。
- **录入更正**：当前值表 + 全量版本表，保留录入人、版本号、时间戳；
  工作台自身的 `wb_requests` 同样支持同号复读/异文拒绝。
- **提交**：
  1. 差异按冻结口径 `counted − frozen_qty` 计算，晚录入、迟提交不改口径；
  2. 非负检查针对**提交时当前库存**（冻结后的移动/收发参与计算），
     任一位置会变负 → 抛 `NegativeAdjustmentError`，整单保持 `open`，不部分提交；
  3. 通过后在同一事务内调用账本 `publish_adjustment_in_tx` 发布调整、
     写调整行、关闭单据、释放位置占用；
  4. 调整请求号 `count-adjust:sheet{id}:{request_no}` 稳定，
     响应丢失后同请求重试复读同一 `adjust_commit_seq` 与同一组调整身份；
  5. 不同请求号对已关闭单据再次结算 → `SheetStateError`。
- **作废**：仅 `open` 单据可作废，释放占用、不生成任何调整、不产生账本序号。
- **可解释**：`explain_sheet` 给出冻结前缀、快照基准、录入版本、
  冻结后逐事件（经账本公开 `events_touching`）、当前量与最终调整。

### 并发

- 进程内：可重入锁串行化写事务；
- 跨进程/跨连接：SQLite 写锁 + 全部主键/唯一约束兜底。
  同请求号并发提交由 `l_requests.PRIMARY KEY` 与 `wb_requests.PRIMARY KEY`
  收敛为一次生效，不会重复调增/调减（`demo.py` 场景 7 与跨进程测试覆盖）。

### 独立核账（`audit.py`）

不调用任何业务方法，直接 `SELECT` 事件表重放，核对：

1. `commit_seq` 连续递增、请求号唯一；
2. 重放全量 == `l_balances` 当前量且全部非负；
3. 每份快照 == 其前缀上的独立重放；
4. 每张盘点单的冻结基准 == `as_of(k)`、差异 == 盘点 − 冻结、
   调整事件序号与落账一致、调整后非负；作废单无调整；
5. 位置占用表与 open 单据状态严格一致；
6. 工作台幂等回执请求号唯一。

核账为纯读操作，失败前后重跑逐行不变。

## 运行

```bash
python3 demo.py          # 10 个场景全部跑完，末尾打印数据库文件目录
python3 audit.py <db>    # 对任意库文件独立核账
```

场景覆盖：手算例、移动两侧原子性、差异导致当前不足、重叠盘点、录入更正、
快照独立核对、线程与跨进程并发、关闭重开持久化、工作台确定性压力链路、
合成事件流（≤10 SKU / ≤10 库位 / ≤500 操作 / ≤20 盘点单）。

## 约束与边界

- 数量一律非负整数，布尔/浮点/负数/零入出库均拒绝；
- 合成跑批固定种子，两次复跑输出逐行一致（临时文件路径除外）；
- 不涉及扫码硬件、成本计价与真实时间穿越测量；
- 表结构可替换（串行事务 + 快照物化 + 事件重放三种手段均有使用），
  但关闭重开后在途盘点单、快照与幂等回执均持久成立。
